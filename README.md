# Сервис сокращения ссылок (URL Shortener)

Консольный клиент-серверный сервис сокращения ссылок с управлением лимитом
переходов и временем жизни (TTL) ссылки. Сетевой слой построен на **Java NIO**
(неблокирующин каналы + `Selector`).

## Возможности

- **Сокращение ссылок**: длинный URL превращается в короткую ссылку вида
  `clck.ru/3DZHeG`. Код уникален в системе, поэтому **разные пользователи
  получают разные короткие ссылки на один и тот же URL**.
- **Лимит переходов**: при создании ссылки можно задать максимальное число
  переходов. После исчерпания лимита ссылка блокируется.
- **Время жизни (TTL)**: срок действия задаётся **системой** (по умолчанию
  сутки, настраивается в конфиге), а не пользователем. Протухшие ссылки
  автоматически удаляются фоновым планировщиком.
- **Уведомления**: владелец получает уведомление, когда лимит исчерпан или
  срок жизни истёк (команда `notifications`, плюс дублирование в лог сервера).
- **Идентификация по UUID**: без авторизации. UUID генерируется при первом
  обращении и сохраняется клиентом в `~/.urlshortener-uuid`. Все операции
  редактирования/удаления доступны **только владельцу** ссылки.
- **Переход из консоли**: команда `open` запрашивает исходный URL у сервера и
  открывает его в браузере через `Desktop.getDesktop().browse(...)`.
- **Мультипользовательский режим**: несколько пользователей и несколько
  ссылок у одного пользователя, данные изолированы по UUID.

## Требования

- JDK 25 (или новее)
- Maven 3.9+

## Запуск

Сначала сервер, затем клиент (в отдельном терминале).

```bash
# сборка
mvn compile

# сервер (порт и параметры — из config/app.properties)
mvn exec:java -Dexec.mainClass=se.ifmo.ru.server.MainServer

# клиент
mvn exec:java -Dexec.mainClass=se.ifmo.ru.client.MainClient
```

## Команды клиента

| Команда | Описание |
| --- | --- |
| `shorten <url> [лимит]` | сократить ссылку (лимит переходов опционален) |
| `open <код>` | перейти по короткой ссылке (откроется браузер) |
| `list` | показать мои ссылки (код, переходы, статус, URL) |
| `update <код> [лимит]` | изменить лимит переходов (только владелец) |
| `delete <код>` | удалить ссылку (только владелец) |
| `notifications` | показать новые уведомления |
| `help` | справка |
| `exit` | выйти |

Примеры:

```
> shorten https://www.baeldung.com/java-9-http-client 5
Готово! Короткая ссылка: clck.ru/3DZHeG
  лимит переходов: 5
  истечёт:        17.11.2026 18:00:00
  открыть:        open 3DZHeG

> open 3DZHeG
Переход учтён, осталось переходов: 4
Открываю: https://www.baeldung.com/java-9-http-client
```

## Конфигурация

Все ключевые параметры читаются из файла `config/app.properties` в рабочей
директории. Если файла нет, используются значения по умолчанию из ресурсов
(`src/main/resources/config/app.properties`).

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `server.port` | `8080` | порт сервера (`0` - свободный) |
| `server.host` | `127.0.0.1` | адрес сервера |
| `link.ttl.seconds` | `86400` | время жизни ссылки, сек (задаётся системой) |
| `link.code.length` | `6` | длина кода короткой ссылки (base62) |
| `link.default-max-visits` | `100` | лимит перкходов по умолчанию |
| `link.max-visits-limit` | `1000000` | максимально допустимый лимит |
| `purge.interval.seconds` | `60` | периодичность автоудаления протухших ссылок |
| `short.url.prefix` | `clck.ru/` | префикс короткой ссылки |

Чтобы переопределить параметры, создайте `./config/app.properties` и укажите
нужные значения.

## Архитектура

Слои:

- **`common`** — протокол: `Message`, `MessageType`, DTO, сериализация
  (Jackson), транспорт «одно JSON-сообщение на строку».
- **`core`** — бизнес логика: `UrlShortenerService`, `ShortLink`,
  `ShortCodeGenerator`, `UrlValidator`, `NotificationService`.
- **`infra`** — инфрструктура: `AppConfig` (загрузка конфигурации),
  `LinkRepository` + `InMemoryLinkRepository` (хранилище).
- **`server`** — NIO-сервер: `UrlShortenerServer` (`ServerSocketChannel` +
  `Selector`, один поток на всех клиентов), `CommandDispatcher` и команды
  (`AuthorizeCommand`, `ShortenCommand`, `RedirectCommand`, `ListCommand`,
  `UpdateCommand`, `DeleteCommand`, `NotificationsCommand`).
- **`client`** — консольный клиент: `MainClient` (CLI), `ClientSession`
  (неблокирующий `SocketChannel` + `Selector`), `UserUuidStore`.

### Сетевой слой на NIO

Сервер использует неблокирующий `ServerSocketChannel`, зарегистрированный в
`Selector`. Один поток обрабатывает события `OP_ACCEPT` / `OP_READ` /
`OP_WRITE` для всех клиентов. Чтение и запись могут быть частичными, поэтому
для каждого соединения ведутся входящий буфер накопления строк и исходящий
буфер с дописыванием/дочитыванием в цикле.

Клиент подключается через `SocketChannel` в неблокирующем режиме:
`OP_CONNECT → finishConnect() → OP_WRITE → OP_READ`, ответ нкапливается в
`ByteBuffer` до получения полной строки.

## Тестирование

```bash
mvn test
```

- **Unit-тесты**: валидация URL, генератор кодов, бизнес-логика сервиса
  (уникальность, лимит, TTL, права владельца, purge), уведомления,
  конфигурация, сериализация протокола.
- **Интеграционные тесты** (`IntegrationTest`): реальные серверы + реальные
  сокет-клиенты, сценарии из ТЗ - уникальность кодов у разных пользователей,
  учёт и блокировка по лимиту, истечение TTL, права владельца, уведомления.

Всего 59 тестов.
